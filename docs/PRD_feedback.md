# PRD 피드백 — 게임 다이나믹/재미 보강

> **대상**: `docs/PRD.md` v1.3
> **작성일**: 2026-05-09
> **목적**: 4종 미니게임의 텐션·다이나믹·구현 명세 보강 지침. PRD 수정 시 본 문서를 기준으로 §4 / §7 / Phase 일정을 갱신한다.

---

## 0. 전체 평가

**현재 골격**: 4게임 모두 "Step-based Random + 페이크 아웃 4종"이라는 동일한 패턴. 안전하지만 **게임 간 차별화가 약하고**, 페이크 아웃이 모두 *결과 직전*에 몰려 있어 게임 중반 텐션이 비어있음.

### 공통 보강 포인트 (모든 게임 §7에 추가)

1. **중반 이벤트 슬롯 신설**
   - 인트로(3.5s) → 본 게임(6~25s) → 결정. 본 게임 구간이 "그냥 흘러가는" 느낌.
   - 본 게임 시간의 30~60% 지점에 **중간 이벤트** 1회 트리거 (게임별 정의). 결과 불변, 순위표 변동 없음.

2. **카메라 워크 명세화**
   - 현재 슬로우모션·줌인은 결정 순간만. 게임 중에도 "선두 추격 카메라", "다크호스 줌인" 같은 동적 카메라가 필요.
   - 게임별로 카메라 모드를 1~2개 정의 (예: `follow-leader`, `pip-closeup`).

3. **시각적 캐스터 멘트 (사운드 무음 정책의 보완)**
   - 좌하단 1줄 캡션 영역. 트리거 기반(선두 변경, 막판 추격, 마지막 라운드 등).
   - 폰트: `caption` 14px / 500. 색: `on-dark` 화이트. 페이드 인/아웃 0.3s.

4. **실시간 라이브 보드**
   - 큰 화면 시연 시 본인이 몇 등인지 추적이 어려움. 우상단 mini leaderboard (현재까지 확정된 순위 누적).
   - 룰렛·로또에서 특히 필수, 경주마·폭탄은 선택.

## 1. 🐎 경주마 (Coral) — 가장 평이함

### 현재 상태 (PRD §7.4)
- 매 프레임 가속도 추첨 + 4종 페이크 (막판 흔들림/사진판정/다크호스/스턴).
- 권장 인원 2~12명, 길이 12~20초.

### 문제점
- 12명 상한이 빡빡함. "매 프레임 가속도 추첨"만으로는 시각 변화가 단조로움(다 비슷한 속도로 보임).
- 페이크가 전부 *후반* 한정 — 전반·중반은 텐션 공백.

### 추가 제안
- **부스터 타일**: 트랙에 시각적 부스터 구간(코랄 글로우 띠). 통과 시 일시적 가속(결과 불변, 페이크 아웃의 한 종류로 명세).
- **스턴/넘어짐을 풍부하게**: 단순 마크가 아닌 **0.5초 정지 모션 + 일어남**. 다크호스는 후방에서 단계적 추월 *3프레임* 강조.
- **선두 캐스터 텍스트**: 좌하단 1줄 자막. ("3코너 진입!", "사진판정!")
- **결승 ceremony**: 1등 통과 후 2~3등이 슬로우로 골인 → 메달 0.8초 정지.
- **카메라**: 선두 그룹만 따라가는 시네마틱 모드 도입 시 **상한 16명까지 확장 가능**.

### 구현 난이도
**낮음.** SVG/CSS 트랜지션 기반이면 부스터·자막·다크호스 모두 추가 비용 작음.

### PRD 수정 지점
- §4 표: 권장 인원 `2~12명` → `2~16명` (시네마틱 모드 도입 시).
- §7.4: 페이크 아웃에 "부스터 타일" 추가, "캐스터 캡션" 항목 추가, 결승 ceremony 명세 추가.

## 2. 🎱 럭키 로또 (Forest) — 시각적 약점 위험

### 현재 상태 (PRD §7.5)
- matter.js 추첨기 + 출구 추출 + 4종 페이크 (출구 멈칫/2공 경합/회전 정지/역회전).
- 권장 인원 2~30명.

### 문제점
- 30명에서 추첨기 내부가 **공의 인지 한계 초과** (서로 가려짐).
- "회전 정지/역회전" 페이크는 *기계 동작*이라 캐릭터 동일시감이 약함.
- 추출 후 화면 한쪽에 쌓이는 부분이 미명세.

### 추가 제안
- **추출 트레이 명세**: 공이 출구로 빠지면 화면 하단에 **순서대로 정렬되는 트레이**. 실시간 순위표 형성.
- **공 클로즈업 PIP**: 출구 직전 공 1개에 picture-in-picture 줌. 누가 추출되는지 명확히.
- **추첨기 가속 페이크**: 회전 가속으로 공이 격렬히 섞이는 5프레임. 20명 이상에서 임팩트.
- **공 색상 정책 명시**: 시그니처 팔레트 5종을 30명에 분배하면 6명당 같은 색 → 식별 어려움. **이름 텍스트가 1차 식별, 색은 보조**임을 명시.
- **30명 → 25명 검토**: 또는 26명+ 모드는 추출구가 더 큰 "벌크 모드" 시각으로 분기.

### 구현 난이도
**중.** matter.js 추첨기 + 트레이 + PIP. matter.js 친숙도에 따라 변동.

### PRD 수정 지점
- §4 표: 권장 인원 `2~30명` → `2~25명` 검토 또는 `26~30명: 벌크 모드` 부기.
- §7.5: "추출 트레이", "PIP 클로즈업", "추첨기 가속" 페이크 추가, 공 색상 식별 정책 명시.

## 3. 💣 폭탄 돌리기 (Surface Dark) — 가장 잠재력 큼, 가장 미세하게 명세됨

### 현재 상태 (PRD §7.6)
- 원형 배치, 중앙 폭탄, max(rank) 라운드, 점점 빨라지는 불꽃.
- 페이크 아웃: 카운트다운 정지 / 속도 변화 / 거짓 폭발 / 방향 반전.

### 문제점
- "원형 배치 + 도화선이 사람 사이를 도는" 메커니즘이 명세에서 **추상적**. 도화선이 어떻게 보이는지, 폭탄이 손에서 손으로 넘어가는지, 한 사람 위에서 도는지 불분명.
- max(rank) 라운드는 직접 입력 7등 같은 케이스에서 7라운드 진행. 라운드 사이 빈 시간 처리가 없음.
- 20명 원형은 인당 18도 → 누가 다음인지 트래킹 어려움.

### 추가 제안 (가장 큰 기회)

**메커니즘을 둘 중 하나로 못 박기**:
- **(A) 핫 포테이토**: 폭탄이 사람 사이를 *물리적으로* 던져짐 (포물선 모션). 받는 사람이 다음 사람에게 패스. → 시각적으로 우월, 구현 부담↑.
- **(B) 회전 인디케이터**: 원 중심에 폭탄, 화살표가 회전하며 가리키는 사람에게 도화선이 옮겨감. → 단순, 20명에서도 안정.

**권장**: (A) 채택. 단 패스 모션은 베지어 + 타이밍 큐로 처리하고 matter.js는 사용하지 않음.

**기타**:
- **디지털 타이머**: 폭탄 표면에 카운트다운 숫자(5 → 0).
- **라운드 간 인터미션 0.8초**: 폭발한 사람 클로즈업 → "💥 7등!" 배지 → 원이 좁혀지며 다음 라운드.
- **잔존자 채도 95% / 탈락자 채도 30%** 명시.
- **속도 자동 조정 공식**: 라운드 N개일 때 라운드별 시간 = `clamp(8s / N, 1.5s, 6s)`. 현재는 "자동 단축"만 적혀있음.

### 구현 난이도
패스 모션(A) 채택 시 **중상**. 베지어 + 타이밍 큐로 충분, matter.js 불필요.

### PRD 수정 지점
- §7.6: 메커니즘 (A)/(B) 명시 + 택1, 디지털 타이머 명세, 라운드 인터미션 0.8초 명세, 잔존/탈락 채도 정책, 속도 자동 조정 공식.
- §3.3: 폭탄 게임 라운드별 시간 공식을 표에 추가.

## 4. 🔴 물리 룰렛 (Mustard) — 50명 한계 가장 큼

### 현재 상태 (PRD §7.7)
- matter.js 못 + 공 + 칸. 4종 페이크 (경계선 멈칫/마지막 튐/연속 추격/느린 낙하).
- 권장 인원 2~50명.

### 문제점
- 50명 = 50칸. 1920px 화면에서 칸당 **38px**. 이름은 거의 못 읽음. 명세는 "식별 가능 폰트"만 적혀있고 **실측 권고치 없음**.
- 공이 한 번에 1개씩 떨어진다면 50명 → 50회 낙하 = 합산 시간 폭주. **동시 낙하인지 순차인지 미명세**.
- 못 격자가 정적이라 페이크 외 *중간 이벤트*가 없음.

### 추가 제안
- **낙하 방식 명시**: "공 1개씩 순차" vs "n개 동시 낙하 후 출구 도착 순". 50명에서 후자가 사실상 강제됨. **"Plinko Tournament" 동시 낙하**로 못 박기.
- **중간 기믹 1종 추가**: 회전 디스크 / 점프대 / 합류 슈트 중 하나. matter.js로 충분히 구현 가능. 단순 못만 있으면 30초가 단조로움.
- **라이브 순위 보드 필수**: 우측 띠에 떨어진 순서 실시간 누적.
- **인원별 칸 폰트 실측치 명세**:
  - 26~50명: 칸폭 ≤ 40px → 폰트 11px / 이름 4자 cut + ellipsis / 이모지 우선 표시.
- **50명 → 권장 초과 경고로 격하** 검토. 30~35명을 진짜 권장치로.

### 구현 난이도
**상.** matter.js 시뮬 + 카메라 + 동시 낙하 처리 + 칸 충돌. 명세를 더 빡빡하게 안 박으면 Phase 4가 무너짐.

### PRD 수정 지점
- §4 표: 권장 인원 `2~50명` → `2~35명 (50명까지 가능, 권장 초과 경고)`.
- §7.7: 낙하 방식(동시) 명시, 중간 기믹 1종 명세, 라이브 보드 추가, 칸 폰트 실측치 표 추가.
- §6.7 인원 적응형 UX 표에 룰렛 35명 임계점 반영.

## 5. 구현 난이도 재평가

| 게임 | PRD Phase 일정 | 실제 체감 | 주요 리스크 |
|---|---|---|---|
| 경주마 | 1.5일 (로또 합산) | **0.7일** | 낮음 |
