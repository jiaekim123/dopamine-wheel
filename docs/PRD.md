## 1. 프로젝트 개요

### 1.1 한 줄 정의
> **회의·회식·발표 자리에서 큰 화면에 띄워놓고, 단 한 번의 게임으로 당첨자를 결정하는 도파민 폭발형 웹앱.**

### 1.2 핵심 가치
- **결과가 아닌 과정**이 주인공. 결정되기까지의 긴장감을 시각적으로 극대화.
- **설치 없음, 접속 즉시 사용**. 정적 호스팅 기반 SPA.
- **공정성은 게임 진행 중 매 순간 실시간 추첨**으로 확보 (§3.2 참조).
- **조용함과 폭발의 대비**(Hybrid Editorial + Dopamine, §10): 메인 화면은 절제된 에디토리얼 톤, 게임은 다크 도파민 모드로 전환되어 임팩트 극대화.

### 1.3 타겟 사용 환경
- **1순위**: 데스크톱 / 노트북 브라우저 (큰 화면 공유 시나리오)
- **2순위**: 태블릿
- **모바일은 부가 대응** (레이아웃 깨지지 않는 수준)

### 1.4 사용 시나리오 예시
- 회식 자리에서 노트북 펼쳐놓고 "오늘 커피 누가 사?" 결정
- 사무실에서 모니터에 띄워놓고 "이번 주 발표자" 뽑기
- 회의실 빔프로젝터에 쏴놓고 단체 추첨 이벤트
- 친구 모임에서 "벌칙 누가?" 결정
- "10명 중 7번째로 결승선 통과한 사람이 사기" 같은 *특정 순위 지목* 시나리오

### 1.5 핵심 정책
| 항목 | 정책 |

| 게임 진행 방식 | **단 한 번에 모든 결과 결정** (토너먼트·재경기 없음) |
| k(당첨자 수) > 1 진행 | **한 게임에서 동시에 k명 결정** (라운드 반복 없음) |

## 3. 핵심 시스템 설계

### 3.1 무작위 소스 — Web Crypto API

```js
// 0 이상 max 미만의 무편향 정수
export function randInt(max) {
  if (max <= 0) throw new Error('max must be > 0');
  const limit = Math.floor(0xFFFFFFFF / max) * max;
  const buf = new Uint32Array(1);
  while (true) {
    crypto.getRandomValues(buf);
    if (buf[0] < limit) return buf[0] % max;
  }
}

export function randFloat() {
  const buf = new Uint32Array(1);
  crypto.getRandomValues(buf);
  return buf[0] / 0x100000000;
}

export function shuffle(arr) { /* randInt 기반 Fisher–Yates */ }
```

테스트 빌드(`import.meta.env.MODE === 'test'`)에서는 mulberry32 PRNG로 대체 (재현성 검증용).

### 3.2 공정성 로직 — Step-based Random

**원칙**: n등을 미리 정해두지 않고, 게임 진행 중 매 step마다 무작위 추첨 → 시뮬 결과 그대로가 결과.

**핵심 정책**: 게임은 항상 **참가자 전원의 rank 1 ~ n 순위표를 자연스럽게 만들어낸다**. 당첨 방식(`first` / `last` / `custom`)은 그 순위표에서 어떤 위치를 골라낼지의 차이일 뿐, 시뮬 자체에는 영향을 주지 않는다.

**페이크 아웃**: 결과를 바꾸지 않는 시각 효과 (트리거 기반 또는 시각적 페이크). 같은 패턴이 직전 게임과 연달아 나오지 않도록 last-pattern memo 유지.

### 3.3 게임 시간 정책
| 항목 | 값 |
|---|---|
| 게임 최소 길이 | **10초** (인트로 3.5초 제외) |
| 게임 최대 길이 | **90초** (1분 30초) |
| 페이크 아웃 추가 시간 | 게임당 합산 ≤ 8초 |
| 슬로우모션 누적 | 게임당 ≤ 3초 |

폭탄 게임은 max(rank) 만큼 라운드 진행. 라운드 수가 많으면 라운드당 시간 자동 단축 (90초 보장).

### 3.4 접근성
- 키보드: Tab으로 모든 인터랙션 도달 / ESC로 메인 복귀 / Enter·Space로 게임 시작
- v1.4: **광과민성 대응 없음.** 모든 연출은 항상 Full 강도로 적용. `prefers-reduced-motion` 미존중.

## 5. 화면 구성 및 플로우

### 5.1 화면 목록 + 디자인 모드
| 화면 | 디자인 모드 |
|---|---|
| **Home** (참가자 입력 + 옵션 + 게임 선택) | **Editorial Mode** (화이트 캔버스 + 시그니처 컬러 카드) |
| **Intro** (카운트다운 3-2-1) | **Transition** (Editorial → Dopamine 1.5초 페이드) |
| **Play** (게임별 진행) | **Dopamine Mode** (다크 베이스 + 시그니처 컬러 강조) |
| **Result** (당첨자 발표) | **Dopamine Mode** (다크 베이스 + Confetti) |

### 5.2 플로우 다이어그램

```
[Home — Editorial Mode]
  ├─ 참가자 입력 (textarea, 쉼표/엔터/공백 파싱, 동명이인 자동 접미)
  ├─ k 설정 (자유 입력, 범위 초과 시 빨간 경고)
  ├─ 당첨 방식 (첫번째 / 마지막 / 직접 입력)
  │    └─ 직접 입력 시: k개의 순위 입력
  └─ 게임 카드 4종 (시그니처 컬러 풀블리드)
       │
       ▼ (게임 선택)
[Intro — Transition]
  ├─ Editorial 화면 위로 다크 오버레이가 페이드인
  ├─ 선택한 게임의 시그니처 컬러로 화면 전환
  ├─ 카운트다운 3 → 2 → 1 → GO!
  └─ 카메라 줌인 효과
       │
       ▼ (자동 전환)
[Play — Dopamine Mode]
  ├─ 다크 베이스 + 시그니처 컬러 강조
  ├─ 게임별 메커니즘 진행 (Step-based Random)
  ├─ 페이크 아웃 (결과 불변)
  └─ 결정 순간: 슬로우모션 + 셰이크 + 플래시 (항상 Full 강도)
       │
       ▼ (자동 전환)
[Result — Dopamine Mode]
  ├─ 당첨자 시그니처 컬러 카드 (k명 그리드, 순위 배지)
  ├─ Confetti 폭발 (시그니처 팔레트)
  ├─ "다시 하기" (Primary) → 같은 게임 즉시 재실행 — 페이드 없이 인트로로 직행
  └─ "처음으로" (Secondary) → [Home/게임 선택] — 참가자·k·당첨 방식 모두 유지, 게임 상태(결과·선택 게임)만 리셋 — Editorial Mode로 페이드 (v1.4.2 / v1.5.1)
```

### 5.3 모드 전환 규칙
- Editorial → Dopamine: Intro 단계에서 1.5초 다크 오버레이 페이드 + 시그니처 컬러 침투
- Dopamine → Editorial: Result에서 액션 버튼 클릭 시 0.6초 화이트 페이드
- ESC 시 어디서든 즉시 Editorial Home으로 복귀 (확인 모달은 Dopamine Mode 베이스에서)

### 6.3 참가자 입력 사양
- 입력 구분자: 쉼표 / 줄바꿈 / 공백
- multiplier syntax 미지원 (`*` 일반 문자)
- 동명이인 자동 `#1`, `#2` 접미
- 빈 문자열 자동 제거 / 양 끝 공백 정리 / 연속 공백 1개로
- 최대 글자 수: 이름당 20자
- 최대 인원: 50명

**시각화** — 이모지 칩 (`rounded-full`)
- 이모지 풀 60+종 (동물 + 과일 + 음식 + 천체)
- FNV-1a 해시 기반 안정 매핑

**자동 저장**: debounce 500ms 후 localStorage

### 6.4 당첨자 수 (k) — v1.4 자유 입력
- `-` / 숫자 / `+` 버튼
- **상한 없음**: `+` 버튼은 항상 활성. n명을 넘는 값도 자유롭게 입력 가능.
- **하한 1**: `-` 버튼은 k=1에서 비활성.
- 디폴트: 1
- **범위 초과 경고**: `k ≥ n` 또는 `n < 2`일 때 카운터 아래에 빨간 경고 텍스트 노출 (예: "당첨자 수가 참가자(N명)와 같거나 많아 게임이 성립하지 않습니다."). 입력 자체는 막지 않으며, 게임 카드는 §6.6 비활성화 규칙(`isGameStartable`)으로 차단된다.
- v1.3까지 있던 `※ 1 ≤ k < n` 안내 문구는 삭제.

### 6.5 당첨 방식 (3가지 모드)

| 모드 | 의미 |
|---|---|
| 첫번째 (default) | 1등부터 k명 |
| 마지막 | 꼴등부터 k명 |
| 직접 입력 | 사용자가 k개 순위를 콤마/공백 구분으로 직접 입력 |

**직접 입력 검증**
| 조건 | 처리 |
|---|---|
| 입력 개수 ≠ k | 경고 + 게임 카드 비활성화 |
| 동일 순위 중복 | 경고 + 게임 카드 비활성화 |
| 순위 < 1 또는 > n | 경고 + 게임 카드 비활성화 |
| 숫자 외 문자 | 입력 단계에서 무시 |

**게임별 의미**
| 게임 | 첫번째 | 마지막 | 직접 입력 |
|---|---|---|---|
| 경주마 | 결승선 1~k등 | 결승선 (n-k+1)~n등 | X번째 도착 |
| 로또 | 첫 추출 k개 | 마지막 남은 k개 | X번째 추출 |
| 폭탄 | 첫 폭발 ~ k회째 걸린 사람 | 마지막에 살아남은 k명 | X번째 폭발 (총 max(X)회 진행) |
| 룰렛 | 가장 먼저 빠지는 k개 | 가장 마지막에 빠지는 k개 | X번째로 빠지는 공 |

### 6.6 게임 선택 카드 (시그니처 컬러 풀블리드)

**카드 디자인 (Editorial Mode 안의 시그니처 카드)**
- `rounded-lg` (12px) 코너
- 내부 패딩 `xxl` (48px)
- 배경: 게임별 시그니처 컬러
  - 🐎 경주마: Coral `#aa2d00` + 화이트 텍스트
  - 🎱 로또: Forest `#0a2e0e` + 화이트 텍스트
  - 💣 폭탄: Surface Dark `#181d26` + 화이트 텍스트
  - 🪂 룰렛: Mustard `#946d12` + 화이트 텍스트 (v1.4.1: AA-safe 다크 머스타드)
- 카드 내용: 큰 이모지 + 게임명 + 권장 인원 + 한 줄 설명
- 호버 모션: 살짝 위로 떠오름 (translateY -4px) + 그림자는 없음 (Airtable 스타일은 그림자 없음, 색 블록 우선)
- 권장 인원 초과 시: 카드 채도 70%로 낮춤 + "⚠️ 권장 초과" 배지 (선택은 가능)

**카드 비활성화 조건**
- n < 2
- k = 0 또는 k ≥ n
- 당첨 방식 = 직접 입력 + 검증 실패
- 비활성화 시 카드 채도 30% + 클릭 차단

### 6.7 인원 적응형 UX
| 인원 | 영향 |
|---|---|
| n < 2 | 모든 게임 비활성화 + "최소 2명 필요" + KCounter 빨간 경고 |
| n > 권장치 | 해당 카드 경고 배지 |
| n > 50 | 입력 차단 + 토스트 |
| k ≥ n | **(v1.4) 클램프 없음.** 빨간 경고만 노출, 게임 카드는 비활성. |

## 7. 게임별 상세 명세 (Dopamine Mode)

### 7.1 공통 인트로 시퀀스 (Transition Mode, 총 3.5초)
1. **0.0~0.5초**: Editorial 화면 위로 선택한 게임의 시그니처 컬러 오버레이가 페이드인 (투명도 0→0.85)
2. **0.5~1.0초**: 시그니처 컬러 베이스에서 다크 베이스 `#0d1218`로 페이드 (게임에 따라 다크 톤 ↓)
3. **1.0~3.0초**: 큰 숫자 "3" → "2" → "1" (각 0.7초, 카메라 줌인)
4. **3.0~3.3초**: "GO!" 플래시 (시그니처 컬러 + 화이트)
5. **3.3~3.5초**: 자동으로 게임 플레이 화면 전환

#### 7.1.1 폭탄 인트로 보강 (v1.5)
폭탄의 시그니처 컬러 `#181d26` (Surface Dark)는 다크 베이스 `#0d1218`과 거의 동일해 1단계 페이드인 효과가 시각적으로 사실상 보이지 않는다. 따라서 폭탄에 한해 **인트로용 액센트 컬러로 Coral `#aa2d00` 침투**를 적용한다.

- 0.0~0.5초: 다크 베이스 위로 Coral 글로우 + Surface Dark 박스 가운데 도화선 불꽃 등장 (투명도 0→0.85)
- 0.5~1.0초: Coral 글로우 페이드아웃, 도화선이 점진적으로 짧아지며 다크 베이스로 흡수
- 카운트다운 단계는 공통 시퀀스 그대로

### 7.2 공통 결정 순간 연출 (v1.4 — 항상 Full)
- **슬로우 모션**: 결정 0.3~0.5초 전 시간 흐름 30%로 감속
- **화면 흔들림**: 결정 순간 0.2초 진동
- **플래시**: 0.1초 백색 + 시그니처 컬러
- **줌인**: 당첨 대상에 카메라 줌

**직접 입력 모드 추가**: 화면 한쪽에 순위 카운터 표시 (예: "1등, 2등, … 7등"). 당첨 순위에 해당하는 도착에서만 슬로우모션 + 플래시.

### 7.3 페이크 아웃 시스템
- 게임 시작 시 페이크 아웃 개수 추첨: **0개 25% / 1개 55% / 2개 20%**
- 같은 패턴이 직전 게임과 연달아 나오지 않도록 last-pattern memo
- 결과를 바꾸지 않는 시각 효과만

### 7.3a 공통 시스템 (v1.5 신설 — `docs/PRD_feedback.md` 반영)

PRD_feedback에서 제안한 공통 텐션 보강 시스템 4종을 명세한다.

#### (1) 캐스터 캡션 (Caster Caption)
- 좌하단 1줄 자막 영역. 사운드 무음 정책의 시각 보완.
- 폰트: `caption` (14px / 500), 색: `on-dark` 화이트, 페이드 인/아웃 0.3초.
- **트리거 기반** — 게임별로 정의. 한 게임 안에 동시 노출 1줄.
- 메시지 큐: 5초 초과 정체되지 않도록 후속 트리거가 우선권.
- 게임별 트리거 예시:
  - 경주마: "1코너 진입!", "사진판정!", "다크호스 등장!"
  - 로또: "warmup 휘젓는 중…", "추출 시작!", "출구 임박!"
  - 폭탄: "Round X 시작", "fuse 위험권", "💥 X등 결정!"
  - 룰렛: "공 N 투입", "막판 추격!", "{이름} 빠짐!"

#### (2) 채도 정책 (Saturation Policy)
- 게임 진행 중 시각 차별화의 일관 규칙.
- **잔존자 / 진행 중 객체**: 채도 100% (기본)
- **탈락자 / 결정된 객체**: 채도 30%, opacity 0.45
- **다크호스/페이크 강조**: 채도 110% + 시그니처 글로우 0.4초

#### (3) 공 색상 정책 (Ball Color Policy — 로또/룰렛 공통)
- 시그니처 팔레트 6색 (coral / peach / mint / yellow / mustard / cream) 순환 매핑.
- **이름이 1차 식별자**, 색은 보조 — n이 색 수보다 많을 때 같은 색 중복 발생 가능. 이름 텍스트(또는 이모지)로 구분.
- 이름 텍스트: 공 지름의 ≥ 35% 폰트 사이즈 보장. 이름이 길면 4자 + ellipsis로 truncate.

#### (4) 라이브 보드 (Live Leaderboard)
- 게임 화면 우측에 누적 순위표를 실시간 노출.
- 폭/스타일 통일: 폭 240~280px, 다크 카드, 최신 항목 강조 (시그니처 글로우 1px 보더).
- **로또 / 룰렛**: 필수 (공 추출 게임 특성상 누가 빠졌는지 추적 어려움).
- **경주마 / 폭탄**: 선택 — 폭탄은 라운드 카운터로 대체, 경주마는 결승 ceremony로 보완.

### 7.4 🐎 경주마 (Horse Race) — Coral

#### 기본 메커니즘
- 베이스: 다크 `#0d1218` + Coral 액센트 (트랙 라인, 결승 라인, 1등 골든 라인은 `#ffd700`).
- 트랙: 잔디 패턴은 어두운 톤, 레인 라인은 Coral.
- 말: SVG 캐릭터 + 이모지 헤드, 이름표는 화이트.
- 매 프레임 가속도 추첨, 전체 rank 1~n 산출.
- 결승선 직전: 자동 슬로우모션 + 줌인 + 당첨 라인 골든 강조.

#### 페이크 아웃 4종 (v1.5 명세)
PRD §7.3 시스템(0/1/2 추첨, last-pattern memo)을 따라 다음 4종에서 추첨:

| 종류 | 트리거 | 시각 효과 (결과 불변) |
|---|---|---|
| **막판 흔들림** | 선두가 결승 5% 직전일 때 | 0.4초 좌우 wobble (±2px sine) — 페이크 추첨됐을 때만 |
| **사진판정** | 1등과 2등 finishTime 차 < 0.18s | 결승선 위 Gold 배너 + "📸 PHOTO FINISH" 텍스트 |
| **다크호스** | 게임 시간 60% 지점 + 후방 하위 30% 중 1마리 | 0.4초 Coral 강조 + "🌟 DARK HORSE" 캡션 + 채도 110% |
| **스턴 마크** | 게임 시간 30~50% 무작위 + 중위권 1마리 | 0.5초 정지 모션(시각만) + ⭐ 회전 마커 |

추첨 순서:
1. 게임 시작 시 `randInt(100)`로 페이크 개수 결정 (0=25%, 1=55%, 2=20%).
2. 페이크가 1개 이상이면 4종 중 무작위 선택 (last-pattern memo로 직전 게임의 마지막 페이크 종류는 제외).
3. 트리거 조건 충족 시 1회만 발동.
4. 사진판정은 자동 트리거(조건부)이며 페이크 추첨과 별개로 발생 가능.

#### 결승 ceremony (v1.5 신설)
- 1등 통과 후 즉시 finishGame을 호출하지 않고 **2~3등이 슬로우모션으로 골인**할 때까지 대기.
- 1등 통과 시점부터 **카메라 줌**이 1등 라인에 잠시 고정 (0.6초).
- 2~3등 통과 시 슬로우 0.5×, 캐스터 캡션 "X등 골인!" 동시 표시.
- 모든 ceremony 종료 후 0.8초 정지 (메달 시각화) → finishGame.
- 권장 인원 12명 유지 (시네마틱 카메라는 v2에서 검토).

### 7.5 🎱 럭키 로또 — Forest

#### 기본 메커니즘
- 베이스: 다크 `#0d1218` + Forest 추첨기 글로우.
- 추첨기: 큰 원형 통, Forest 톤 발광.
- 공: 시그니처 팔레트 6색 순환 (§7.3a (3) 공 색상 정책 준수).
- 출구: Forest 강조 튜브.
- matter.js 시뮬 그대로, 추출 순서 = rank.

#### 2-phase 진행 (v1.5 신설 — `docs/implementation_followup.md` §1 + PRD_feedback §2)
| Phase | 동작 |
|---|---|
| **warmup** | 출구 게이트가 닫혀 있어 공이 챔버 안에서 **3~10초** 무작위로 휘저어진다 (`randFloat()`로 결정성 시드 적용). 추출 0건 보장. |
| **extracting** | 게이트가 열리고 공이 하나씩 추출. 기존 추출 로직. |
| **done** | 모든 공 추출 완료. |

- warmup 동안 캐스터 캡션 "🌪 휘젓는 중…" / 헤더에 phase 배지 (Forest 라이트 톤).
- warmup 종료 시 0.4초 흰색 플래시 + 캡션 "🎱 추첨 시작!".
- warmup 시간은 사용자에게 **노출하지 않음** (긴장감 유지).

#### 공 사이즈 + 텍스트 (v1.5)
- `ballRadius`: 22 → **28** (식별성↑).
- 이름 텍스트 폰트: `Math.round(ballRadius × 0.45)` ≈ 13px.
- 이름 truncate: 7자 + ellipsis (`displayName.length > 7 ? slice(0,6)+'…' : displayName`).
- 이모지 폰트: `ballRadius × 1.0`.

#### PIP 클로즈업 (v1.5 신설)
- `phase === 'extracting'` AND `inTube === true` 조건일 때 화면 우상단 또는 챔버 좌측에 큰 카드 등장.
  - 큰 이모지 (clamp 96~140px)
  - 큰 이름 (32px)
  - 보조 텍스트 "곧 결정 — N등 후보" (N = `state.nextRank`)
- 등장 모션: 0.3초 페이드 + scale 0.8→1, inTube 공이 사라지면 0.4초 페이드아웃.
- 동시에 여러 공이 튜브에 있을 때: y값이 가장 큰 공 1개만 표시.

#### 페이크 아웃 4종 (기존 PRD)
- 출구 멈칫 / 2공 경합 / 회전 정지 / 역회전.
- 추출 연출: 당첨 순위 공만 슬로우모션 + 클로즈업.

### 7.6 💣 폭탄 돌리기 — Surface Dark

#### 메커니즘 — (B) 회전 인디케이터 (v1.5 확정)
PRD_feedback에서 제안된 (A) 핫포테이토 / (B) 회전 인디케이터 중 **(B) 채택**. 핫포테이토(물리 던지기)는 시각적 우월하지만 구현 부담↑·20명에서 안정성↓.

- 참가자가 원형 좌석에 고정 배치 (12시 시작, 시계방향).
- **폭탄이 좌석 사이를 hop으로 패스** (`prevSeat → currentSeat` 보간 모션).
- 패스 인터벌: 0.06~0.32초 무작위 추첨 (자연스러운 가속/감속).
- 5% 확률 패스 방향 반전 (페이크 아웃 — 결과 불변).
- 살아있는 좌석만 hop 대상, 폭사한 좌석은 건너뜀.

#### 라운드 시스템
- max(rank) 라운드 진행 — 직접 입력 모드의 max 순위까지만 폭발 (이후 잔존자는 미정).
- **현재 구현**: n-1 라운드 풀 진행 (모든 rank 산출). max(rank) 최적화는 v2에서 검토.
- `computeBombTimings(n)`: target gameplay 18~24초 안에 들어가도록 fuse + explosion 시간 자동 조정.
- 라운드 카운터: 화면 상단 "라운드 X / Total" (직접 입력 모드 강조).

#### 디지털 타이머 (v1.5 신설)
- 폭탄 표면에 **카운트다운 숫자(N→0)** 텍스트 노출.
- 폰트: `marquee` (Press Start 2P), 화이트.
- 값: `Math.ceil(fuseRemaining)` 정수.
- 도화선 길이 시각화는 그대로 유지 (이중 표현 — 시각 + 숫자).

#### 라운드 인터미션 0.8초 (v1.5 신설)
- 폭발 직후 explosion phase(0.55s) 종료 후 **0.3초 추가 정지** — 총 0.85s.
- 이 동안:
  - 폭사자 좌석에 카메라 줌 (1.2× scale)
  - 큰 배지 노출: "💥 X등!" (Press Start 2P 32px)
  - 캐스터 캡션 "Round X 종료" 표시
- 종료 후 다음 라운드로 전환 (폭탄이 다음 alive seat으로 이동).

#### 채도 정책 (§7.3a (2) 적용)
- **잔존자**: 채도 100%, 화이트 박스.
- **폭사자**: 채도 30%, opacity 0.45, 회색 박스(`#1d1f25`).
- **현재 폭탄 보유자**: Coral 글로우 (drop-shadow 14px).

#### 페이크 아웃 4종
- 카운트다운 정지(0.3초) / 속도 변화(±50%) / 거짓 폭발(플래시만 후 fuse 0.5초 부활) / 방향 반전.
- 폭발 연출: 화면 흔들림 + 백색·Coral 플래시 + 당첨 순위면 Gold 추가 강조.

### 7.7 🪂 운명의 낙하 — Mustard

#### 기본 메커니즘
- 베이스: 다크 `#0d1218` + Mustard 못 글로우.
- 못: 정적 객체, Mustard 톤 발광.
- 공: 시그니처 팔레트 6색 순환 (§7.3a (3) 공 색상 정책 준수).
- 칸: 시그니처 팔레트 그라데이션 (peach/mint/yellow/mustard 순환).
- 트레일: 글로우 잔상.

#### 드롭 방식 — 순차 (v1.5 확정)
PRD_feedback에서 제안된 동시 낙하 / 순차 중 **순차 채택**. 동시는 50명에서 사실상 강제되지만 시각 혼란↑·식별성↓. 순차는 staggered 효과로 동시감 + 추적성 양립.

- `dropQueue` 기반 — 0.12~0.6초 인터벌(인원별 자동 조정)로 위쪽에서 1개씩 투입.
- n=50: 0.12초 × 50 ≈ 6초만에 전체 투입 완료. 이후 튕기는 시간 + exit으로 총 15~30초.

#### 권장 인원 변경 (v1.5)
- **권장 35명** (50명까지 가능, 권장 초과 경고 배지).
- 36~50명은 `getGameAvailability(game, n)`에서 `warn: true` 반환.

#### `button-secondary`
- 배경: `canvas` `#ffffff`
- 텍스트: `ink` `#181d26`
- 보더: 1px `hairline`
- 코너: `rounded-lg` (12px)

#### `game-card`
- 배경: 시그니처 컬러 (게임별)
- 텍스트: 컬러에 따라 화이트 또는 ink (대비 보장)
- 코너: `rounded-lg` (12px)
- 패딩: `xxl` (48px)
- 호버: translateY(-4px), 채도 5% ↑
- 비활성: 채도 30%, 클릭 차단

#### `text-input`
- 배경: `canvas`
- 보더: 1px `hairline`
- 코너: `rounded-sm` (6px)
- 패딩: 12px × 16px
- 포커스: 보더가 `info-border` `#458fff`로

#### `emoji-chip`
- 코너: `rounded-full`
- 배경: 시그니처 보조 톤 (peach/mint/cream 등) 살짝 채도 낮춰서
- 텍스트: `ink`
- 폰트: `caption`

#### `result-box`
- k=1: `rounded-lg` (12px), 게임 시그니처 컬러, `xxl` 패딩
- k≥2: `rounded-md` (10px), 시그니처 + 보조 톤 교차, `xl` 패딩
- 텍스트: Marquee 폰트 (Press Start 2P)
- 순위 배지: 좌상단, 메달 컬러 (gold/silver/bronze/보조 톤)

### 10.9 그리드 & 컨테이너
- 최대 콘텐츠 폭: 1280px (양옆 48px breathing room)
- 게임 카드 그리드: 데스크탑 4-up / 태블릿 2-up / 모바일 1-up
- 전환 시 카드 사이즈 동일 비율 유지 (스펙 시트 느낌 회피를 위해 약간의 높이 변동만 허용)

### 10.10 디자인 Do / Don't

**Do**
- Primary CTA는 **near-black** `#181d26`. 링크색 `#1b61c9`이 아니다.
- 시그니처 컬러는 **풀블리드 카드**로만 사용. 작은 액센트로 흩뿌리지 않는다.
- Editorial Mode 베이스 위에서는 **그림자 대신 색 블록**으로 깊이 표현.
- 디스플레이 텍스트 가중치는 **400 / 500만**. 700은 금지.
- Section padding 96px 고정.
- Confetti는 시그니처 팔레트로만 (네온 RGB 회피).

**Don't**
- 메인 화면에 그라데이션 / 메시 / 오로라 배경 추가 금지 — Airtable의 "신뢰는 여백에서" 철학 위반.
- 디스플레이 폰트 가중치 700 금지.
- Pill 코너 사용 금지 (pricing sub-system이 없음).
- 같은 모드를 두 띠 연속 배치 금지 (예: Editorial 두 카드 연속 → 매거진 블로그처럼 보임). 시그니처 카드가 띠를 끊어줘야 함.
- 시그니처 컬러 외 추가 액센트 컬러 도입 금지 (peach/mint/yellow 등 보조 팔레트로 충분).
