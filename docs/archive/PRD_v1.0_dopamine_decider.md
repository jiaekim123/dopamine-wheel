# 🎰 Dopamine Decider — PRD (Product Requirements Document)

> **버전**: v1.0 (MVP)
> **작성일**: 2026-05-09
> **상태**: 기획 확정 / 개발 착수 대기

---

## 1. 프로젝트 개요

### 1.1 한 줄 정의
> **회의·회식·발표 자리에서 큰 화면에 띄워놓고, 단 한 번의 게임으로 당첨자를 결정하는 도파민 폭발형 웹앱.**

### 1.2 핵심 가치
- **결과가 아닌 과정**이 주인공. 결정되기까지의 긴장감을 시각적으로 극대화.
- **설치 없음, 접속 즉시 사용**. 정적 호스팅 기반 SPA.
- **공정성은 입력 단계에서 확보**. 이름을 입력한 순간 게임이 무작위로 진행되므로 별도 시드 노출 불필요.

### 1.3 타겟 사용 환경
- **1순위**: 데스크톱 / 노트북 브라우저 (큰 화면 공유 시나리오)
- **2순위**: 태블릿
- **모바일은 부가 대응** (레이아웃 깨지지 않는 수준)

### 1.4 사용 시나리오 예시
- 회식 자리에서 노트북 펼쳐놓고 "오늘 커피 누가 사?" 결정
- 사무실에서 모니터에 띄워놓고 "이번 주 발표자" 뽑기
- 회의실 빔프로젝터에 쏴놓고 단체 추첨 이벤트
- 친구 모임에서 "벌칙 누가?" 결정

### 1.5 핵심 정책
| 항목 | 정책 |
|---|---|
| 게임 진행 방식 | **단 한 번에 모든 결과 결정** (토너먼트·재경기 없음) |
| 결과 발표 | 게임 종료 시 당첨자 *k*명을 전광판 스타일로 노출 + Confetti |
| 공정성 표시 | 별도 시드 노출 없음 (입력 단계에서 공정성 확보 간주) |
| 사운드 | **MVP에서는 무음** (시각 요소만으로 도파민 전달) |
| 배포 | 정적 호스팅 (GitHub Pages 등). 서버 없음. |
| 데이터 저장 | localStorage만 사용 (마지막 입력 자동 복원) |

## 2. 기술 스택

| 영역 | 선택 | 비고 |
|---|---|---|
| 빌드 도구 | **Vite** | 빠른 HMR, 정적 빌드 |
| 프레임워크 | **React 18+** | |
| 언어 | **JavaScript** | TypeScript 미사용 (해커톤 속도 우선) |
| 스타일링 | **Tailwind CSS** + `tailwindcss-animate` | 네온 다크 테마 |
| 애니메이션 | **Framer Motion** | 컴포넌트 모션 전반 |
| 물리 엔진 | **matter.js** | 물리 룰렛 전용 |
| Confetti | **canvas-confetti** | 결과 화면 |
| 상태 관리 | **Zustand** | 전역 상태 (참가자, 당첨자 수, 게임 결과) |
| 라우팅 | 없음 | 화면 상태(state)로 전환 |
| 배포 | **GitHub Pages** (또는 Vercel) | 정적 호스팅 |

### 백엔드 / 서버
**없음.** 모든 로직은 클라이언트 JavaScript로 동작. 서버 통신 없음.

### 외부 자산 (멀티모달 옵션)
- **메인 화면 배경 이미지 1장** + **게임별 인트로 배경 4장** (총 5장)
- AI 이미지 생성 도구로 사전 제작 후 정적 자산으로 번들
- 게임 플레이 화면은 100% 코드(SVG/CSS/Canvas) 기반

## 4. 화면 구성 및 플로우

### 4.1 화면 목록
1. **메인 화면 (Home)** — 참가자 입력 + 당첨자 수 설정 + 게임 4종 선택
2. **게임 인트로 (Intro)** — 카운트다운 3-2-1 + 게임 배경
3. **게임 플레이 (Play)** — 각 게임별 진행 화면
4. **결과 화면 (Result)** — 당첨자 발표 + Confetti + "다시" 버튼

### 4.2 플로우 다이어그램

```
[Home]
  ├─ 참가자 입력 (textarea, 쉼표/엔터/공백 파싱)
  ├─ 당첨자 수 k 설정 (1 ≤ k < n)
  └─ 게임 카드 4종 (권장 인원 배지 표시)
       │
       ▼ (게임 선택)
[Intro]
  ├─ 게임 배경 이미지
  ├─ 카운트다운 3 → 2 → 1 → GO!
  └─ 카메라 줌인 효과
       │
       ▼ (자동 전환)
[Play]
  ├─ 게임별 메커니즘 진행
  ├─ 페이크 아웃 연출 (랜덤 발동)
  └─ 결정 순간: 슬로우모션 + 화면 흔들림 + 플래시
       │
       ▼ (자동 전환)
[Result]
  ├─ 당첨자 이름 전광판 (애니메이션)
  ├─ Confetti 폭발
  ├─ "다시 하기" → [Home] (참가자 유지)
  └─ "처음으로" → [Home] (전체 리셋)
```

### 4.3 화면 전환 규칙
- 모든 전환은 Framer Motion 페이드/슬라이드
- 사용자 개입 없이 자동 진행 (Intro → Play → Result)
- 단 [Result] 에서는 사용자 액션 대기

## 5. 메인 화면 상세 명세

### 5.1 디자인 컨셉
- **네온 다크 테마** (#0a0a0f 배경, 네온 핑크/시안/퍼플 강조)
- **게임장 분위기** (격자 라인, 글로우 효과)
- 큰 화면 시연 가정 → 폰트 크게, 여백 넉넉히

### 5.2 컴포넌트 구성

```
┌──────────────────────────────────────────┐
│  🎰 DOPAMINE DECIDER  (네온 로고)         │
│  "오늘의 운명, 누가 가져갈까?"            │
├──────────────────────────────────────────┤
│ [참가자 입력]                              │
│  ┌────────────────────────────────────┐  │
│  │ 김철수, 이영희                       │  │
│  │ 박민수                              │  │
│  │ 정수진 최지원                       │  │
│  └────────────────────────────────────┘  │
│  현재 8명 (이모지 칩으로 시각화)            │
│  🦊 김철수  🐯 이영희  🐰 박민수 ...       │
├──────────────────────────────────────────┤
│ [당첨자 수]  [- 1 +]   ※ 1 ≤ k < n      │
├──────────────────────────────────────────┤
│ [게임 선택]                                │
│  ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐  │
│  │ 🐎   │ │ 🎱   │ │ 💣   │ │ 🔴   │  │
│  │ 경주마│ │ 로또 │ │ 폭탄 │ │ 룰렛 │  │
│  │~12명 │ │~30명 │ │~20명 │ │~50명 │  │
│  └──────┘ └──────┘ └──────┘ └──────┘  │
└──────────────────────────────────────────┘
```

### 5.3 참가자 입력 사양

**파싱 규칙**
- 입력 구분자: **쉼표 `,`**, **줄바꿈 `\n`**, **공백 ` `** 셋 다 인정
- 중복 이름 자동 병합 (뒤의 것 무시)
- 빈 문자열 자동 제거
- 최대 글자 수: 이름당 20자 (초과 시 잘림)
- 최대 인원: **50명** (전체 하드 상한)

**시각화**
- 입력 직후 이름 아래 **이모지 칩**으로 표시
- 이모지 풀: `🦊🐯🐰🐼🐨🦁🐶🐱🐸🦄🐲🐹🦝🐻🐷🐮🐔🐧🦉🦅🦋🐢🐙🦖🦕🐳🦈🐬🦓🦒🦘🦔🦦🦥🦨🦩🦚🦜🦡🐊` (40+종)
- 이름별 안정적 매핑 (해시 기반: 같은 이름은 항상 같은 이모지)

**자동 저장**
- 입력 변경 시 **debounce 500ms** 후 localStorage 저장
- 다음 방문 시 자동 복원
- localStorage 키: `dopamine_decider_last_input`

### 5.4 당첨자 수 (k) 설정

- 입력 UI: **`-` / 숫자 / `+` 버튼**
- 범위: `1 ≤ k < n` (참가자 수 미만)
- 참가자 수 변경 시 자동 보정 (범위 벗어나면 1로 리셋)
- 디폴트값: 1

### 5.5 게임 선택 카드

- 카드 4개를 가로 그리드로 배치
- 각 카드에 표시:
  - 큰 이모지 + 게임명
  - **권장 인원 배지** (예: "👥 권장 12명 이하")
  - 호버 시 글로우 + 살짝 위로 떠오르는 모션
- **현재 참가자 수가 권장치 초과 시**: 카드에 회색 오버레이 + "⚠️ 권장 초과" 배지 추가 (선택은 가능)
- **참가자 수가 2명 미만이거나 k가 0이면**: 모든 카드 비활성화

### 5.6 인원 적응형 UX 규칙

| 인원 수 | 영향 |
|---|---|
| n < 2 | 모든 게임 비활성화 + "최소 2명 필요" 안내 |
| n > 권장치 | 해당 게임 카드에 경고 배지 (선택은 가능) |
| n > 50 | 입력 자체 차단 (50명 초과분 무시) |

## 6. 게임별 상세 명세

### 6.1 공통 인트로 시퀀스 (모든 게임 공통)

**카운트다운 인트로 (총 3.5초)**
1. 게임 배경 이미지 페이드 인 (0.5초)
2. 큰 숫자 "3" 등장 → "2" → "1" (각 0.8초, 카메라 줌인 효과)
3. "GO!" 플래시 (0.3초)
4. 자동으로 게임 플레이 화면 전환

### 6.2 공통 결정 순간 연출

**모든 게임의 "결과 확정 직전"에 적용**
- **슬로우 모션**: 결정 0.3~0.5초 전 시간 흐름 30%로 감속
- **화면 흔들림 (shake)**: 결정 순간 0.2초간 진동
- **플래시**: 결정 순간 화면 전체 0.1초 백색 플래시
- **줌인**: 당첨 대상에 카메라 줌

### 6.3 페이크 아웃 시스템 (전체 게임 공통 원칙)

**핵심 원칙**: "**매번 다른 페이크 아웃**" — 같은 게임을 두 번 돌려도 같은 연출이 나오면 안 됨.

**구현 방식**
- 게임 시작 시 **무작위로 페이크 아웃 패턴 0~2개를 추첨** (게임마다 가능 패턴 풀이 다름)
- 일부 라운드는 페이크 아웃 0개 (담백하게 끝남) → 매번 같은 연출이 아님을 보장
- 페이크 아웃 발동 확률: **약 70%** (게임 중 1회 이상)

각 게임의 페이크 아웃 풀은 아래 6.4~6.7에 명시.

### 6.4 🐎 게임 1: 경주마 (Horse Race)

**기본 메커니즘**
- 가로형 트랙 (좌→우)
- 각 참가자가 말 캐릭터 (이름표 + 이모지)
- 매 프레임 무작위 가속도 변동
- 결승선 도달 순서가 순위
- 상위 *k*명이 당첨

**시각 디자인**
- 트랙: 잔디 패턴 + 레인 라인
- 말: SVG 캐릭터 (간단한 도형 조합 + 이모지 헤드)
- 이름표: 말 위에 떠있는 라벨

**확률 로직**
- 결과는 **시작 직후 무작위로 결정** (당첨자 *k*명 선출)
- 연출은 그 결과로 수렴하도록 가속도를 조정
- 단, 마지막 20% 구간 전까지는 자유 경쟁처럼 보이게

**페이크 아웃 풀** (랜덤 1~2개 선택)
- 🏁 **막판 역전**: 결승선 30m 전 1위가 갑자기 감속 → 후순위 추월
- 📸 **사진판정**: 1·2위 거의 동시 골인, 슬로우모션 후 판정
- 🐴 **다크호스**: 중반 꼴찌가 종반 급가속
- 🌪️ **부진 연출**: 1위가 "결승선 직전 멈칫" 후 다시 가속

**결승선 직전 연출**
- 자동 슬로우모션 (마지막 0.5초)
- 카메라 줌인
- 당첨 라인에 골든 라인 효과

**권장 인원**: 2~12명

### 6.5 🎱 게임 2: 럭키 로또 (Lucky Lotto)

**기본 메커니즘**
- 투명한 추첨기에 이름이 적힌 공들이 떠다님
- 추첨기가 회전하며 공들이 섞임
- 출구로 *k*개의 공이 차례로 추출됨

**시각 디자인**
- 추첨기: 큰 원형 통 (네온 글로우)
- 공: 컬러풀한 구체 + 중앙에 이름
- 출구: 통 하단의 짧은 튜브

**물리 시뮬레이션**
- matter.js 사용 (또는 가벼운 자체 물리)
- 공들이 서로 부딪히며 섞임
- 추첨 시 출구 방향으로 흡인력

**페이크 아웃 풀** (랜덤 1~2개 선택)
- 🎯 **출구 멈칫**: 공이 출구로 빠질 듯 흔들리다가 다시 들어감 (1~2회)
- 🔄 **2공 경합**: 마지막에 2~3개 공이 출구 근처에서 자리다툼
- ⏸️ **회전 정지**: 추첨기가 멈췄다가 다시 회전
- 🌀 **역회전**: 회전 방향이 갑자기 반대로

**추출 연출**
- 공이 튀어나오는 순간 슬로우모션
- 화면 중앙에 공 클로즈업
- 이름이 빛나는 텍스트로 확대

**권장 인원**: 2~30명

### 6.6 💣 게임 3: 폭탄 돌리기 (Time Bomb)

**기본 메커니즘**
- 이름들이 원형으로 배치
- 중앙에서 불꽃(스파크)이 한 사람씩 점프
- 점프 속도가 점점 빨라짐
- 무작위 시점에 폭탄 폭발 → 그 시점에 불꽃이 있던 사람이 "걸림"
- *k*명 뽑을 경우 → 폭발 *k*회 진행

**시각 디자인**
- 원형 배치, 중앙에 폭탄 이미지
- 불꽃은 폭탄 도화선이 타들어가는 형태
- 사람마다 박스 + 이름 + 이모지

**타이밍 로직**
- 초기 이동 속도: 200ms/칸
- 매 칸마다 가속 (최소 50ms/칸까지)
- 폭발 시점은 시작 시 무작위 결정 (3~10초 사이)

**페이크 아웃 풀** (랜덤 1~2개 선택)
- ⏸️ **카운트다운 정지**: 폭발 직전 불꽃이 한 칸에서 정지 → 다시 이동
- 💨 **속도 변화**: 갑자기 느려졌다가 폭주
- 🔥 **거짓 폭발**: 폭발 효과 한 번 나오고 "휴…" 후 진짜 폭발
- 🔄 **방향 반전**: 시계방향 → 반시계방향 갑자기 전환

**폭발 연출**
- 화면 흔들림 + 백색 플래시
- 폭탄 그래픽 폭발 애니메이션
- 걸린 사람만 화면에 남고 나머지 페이드 아웃

**권장 인원**: 2~20명

### 6.7 🔴 게임 4: 물리 룰렛 (Physics Roulette)

**기본 메커니즘** (lazygyu 레퍼런스)
- 화면 상단에서 빨간 공(들)이 떨어짐
- 중간에 못(pegs)이 격자 형태로 박혀 있음
- 공이 못에 부딪히며 좌우로 튐
- 화면 하단에 이름이 적힌 칸들이 가로로 배치
- 공이 빠진 칸의 이름이 당첨

**시각 디자인**
- 어두운 배경 + 네온 못
- 공은 글로우 트레일 효과
- 칸은 무지개 색 그라데이션
- 떨어지면서 트레일이 잔상으로 남음

**물리 엔진**
- **matter.js 필수**
- 공의 반발력·마찰·중력을 미세 튜닝해서 "통통" 튀는 느낌
- 못 배치는 인원수에 따라 자동 조정
- 화면 하단 칸 폭은 인원수에 따라 동적

**확률 로직**
- 결과는 시작 직후 결정 (당첨자 *k*명 선출)
- *k*개의 공을 차례로 떨어뜨림
- 각 공이 정해진 칸에 빠지도록 출발 위치·초기 속도 미세 조정 (육안으로는 자연스러워야 함)
- 또는 자연스러운 물리 결과를 그대로 사용 (시뮬 후 결과 확정 방식)

**페이크 아웃 풀** (랜덤 1~2개 선택)
- 🪤 **경계선 멈칫**: 공이 두 칸 경계에 잠깐 걸렸다 한쪽으로 빠짐
- 🔄 **마지막 튐**: 칸 직전 못에서 마지막으로 크게 튕김
- 🎯 **연속 추격**: 여러 공이 동시에 떨어져 어느 게 당첨인지 헷갈리게
- 💫 **느린 낙하**: 한 공이 유난히 느리게 떨어짐 (긴장 연장)

**결정 순간 연출**
- 공이 칸에 빠지는 순간 슬로우모션
- 칸이 강하게 빛남
- *k*명 모두 결정될 때까지 반복

**인원 수에 따른 칸 배치**
- 2~10명: 큰 칸, 못 격자도 듬성듬성
- 11~25명: 중간 크기
- 26~50명: 칸이 좁아지지만 여전히 명확하게

**권장 인원**: 2~50명

## 7. 결과 화면 상세 명세

### 7.1 구성

```
┌──────────────────────────────────────────┐
│       🎉 당첨자가 결정되었습니다! 🎉      │
│                                          │
│    ╔════════════════════════════╗       │
│    ║                            ║       │
│    ║      🦊  김철수             ║       │
│    ║                            ║       │
│    ╚════════════════════════════╝       │
│                                          │
│    (k명일 경우 추가 박스들)               │
│                                          │
│   [다시 하기]  [처음으로]                 │
└──────────────────────────────────────────┘
```

### 7.2 연출
- 당첨자 이름 박스: **전광판 스타일** (디지털 폰트, 글로우)
- 박스 등장 시 타이핑 효과 + 글리치 애니메이션
- **canvas-confetti**로 색종이 폭발 (3초간 지속)
- 배경에 네온 라이트 펄스 효과

### 7.3 액션 버튼
- **다시 하기**: 같은 참가자·k 유지하고 메인 화면으로 (게임 다시 선택 가능)
- **처음으로**: 참가자 목록과 k 모두 리셋하고 메인 화면으로

## 9. 디자인 시스템

### 9.1 컬러 팔레트 (네온 다크)

| 용도 | 컬러 | HEX |
|---|---|---|
| 배경 | 딥 다크 | `#0a0a0f` |
| 보조 배경 | 다크 그레이 | `#1a1a2e` |
| 메인 강조 (네온 핑크) | 핑크 | `#ff2d92` |
| 보조 강조 (네온 시안) | 시안 | `#00f5ff` |
| 추가 강조 (네온 퍼플) | 퍼플 | `#b026ff` |
| 텍스트 (메인) | 화이트 | `#ffffff` |
| 텍스트 (보조) | 라이트 그레이 | `#a0a0c0` |
| 성공/당첨 | 골드 | `#ffd700` |

### 9.2 타이포그래피
- **로고/헤드라인**: 네온 효과 가능한 굵은 산세리프 (예: `Orbitron`)
- **본문**: 시스템 폰트 또는 `Inter`
- **결과 전광판**: 디지털 폰트 (예: `VT323`, `Press Start 2P`)

### 9.3 효과
- 글로우(box-shadow)는 모든 강조 요소에 기본 적용
- 호버 시 미세한 위로 떠오름 + 글로우 강도 증가
- 트랜지션 기본값: `cubic-bezier(0.4, 0, 0.2, 1)`, 200ms
