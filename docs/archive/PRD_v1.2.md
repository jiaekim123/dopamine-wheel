## 1. 프로젝트 개요

### 1.1 한 줄 정의
> **회의·회식·발표 자리에서 큰 화면에 띄워놓고, 단 한 번의 게임으로 당첨자를 결정하는 도파민 폭발형 웹앱.**

### 1.2 핵심 가치
- **결과가 아닌 과정**이 주인공. 결정되기까지의 긴장감을 시각적으로 극대화.
- **설치 없음, 접속 즉시 사용**. 정적 호스팅 기반 SPA.
- **공정성은 게임 진행 중 매 순간 실시간 추첨**으로 확보 (§3.2 참조).

### 1.3 타겟 사용 환경
- **1순위**: 데스크톱 / 노트북 브라우저 (큰 화면 공유 시나리오)
- **2순위**: 태블릿
- **모바일은 부가 대응** (레이아웃 깨지지 않는 수준)

### 1.4 사용 시나리오 예시
- 회식 자리에서 노트북 펼쳐놓고 "오늘 커피 누가 사?" 결정
- 사무실에서 모니터에 띄워놓고 "이번 주 발표자" 뽑기
- 회의실 빔프로젝터에 쏴놓고 단체 추첨 이벤트
- 친구 모임에서 "벌칙 누가?" 결정
- "10명 중 7번째로 결승선 통과한 사람이 사기" 같은 *특정 순위 지목* 시나리오 (v1.2 신규)

### 1.5 핵심 정책
| 항목 | 정책 |
|---|---|
| 게임 진행 방식 | **단 한 번에 모든 결과 결정** (토너먼트·재경기 없음) |
| k(당첨자 수) > 1 진행 | **한 게임에서 동시에 k명 결정** (라운드 반복 없음) |
| 당첨 방식 | **첫번째 / 마지막 토글 + 직접 입력 옵션** (default = 첫번째) |
| 결과 발표 | 게임 종료 시 당첨자 *k*명을 전광판 스타일로 노출 + Confetti |
| 공정성 표시 | **별도 시드 노출 없음.** 결과는 게임 진행 중 실시간 추첨 (§3.2). |
| 사운드 | **MVP에서는 무음** (시각 요소만으로 도파민 전달) |
| 광과민성 대응 | **"연출 강도" 토글** (Full / Soft / Off) + `prefers-reduced-motion` 자동 감지 |
| 배포 | 정적 호스팅 (GitHub Pages 등). 서버 없음. |
| 데이터 저장 | localStorage만 사용 (마지막 입력·k·옵션 자동 복원) |

## 3. 핵심 시스템 설계

### 3.1 무작위 소스 — Web Crypto API

**선택 이유**
- `Math.random()`은 일부 환경에서 균등 분포 보장이 약함
- 50명 중 1명을 뽑는 시나리오에서 **무편향(unbiased)** 분포가 중요
- 회식·발표 시나리오의 "공정함" 인식에 부합
- 성능 영향 미미

**유틸 함수 (`src/lib/random.js`)**
```js
// 0 이상 max 미만의 무편향 정수
export function randInt(max) {
  if (max <= 0) throw new Error('max must be > 0');
  const limit = Math.floor(0xFFFFFFFF / max) * max;  // 모듈로 편향 제거
  const buf = new Uint32Array(1);
  while (true) {
    crypto.getRandomValues(buf);
    if (buf[0] < limit) return buf[0] % max;
  }
}

// 0 이상 1 미만의 실수
export function randFloat() {
  const buf = new Uint32Array(1);
  crypto.getRandomValues(buf);
  return buf[0] / 0x100000000;
}

// Fisher–Yates shuffle (in-place)
export function shuffle(arr) { /* randInt 기반 */ }

// 테스트용 시드 모드 — 테스트 빌드에서만 활성화
//   import.meta.env.MODE === 'test' 일 때 mulberry32로 대체
```

### 3.2 공정성 로직 — Step-based Random

**원칙**
> "n등을 미리 정해두는 게 아니라, 게임 진행 중 여러 분기점(step)마다 매 순간 무작위로 결정한다."

| 방식 | v1.0 (기각) | v1.1+ (채택) |
|---|---|---|
| 결과 결정 시점 | 게임 시작 직후 사전 결정 | **게임 진행 중 매 step에서 추첨** |
| 연출 | 결과에 수렴하도록 강제 | 자연스러운 진행 결과를 그대로 채택 |
| 신뢰성 | "조작" 인식 위험 | 진짜 무작위 → 신뢰 ↑ |

**게임별 step 정의 요약**
- 🐎 **경주마**: 매 프레임마다 각 말의 가속도를 randFloat로 추첨 → 결승선 통과 순서가 그대로 결과
- 🎱 **로또**: matter.js 물리 시뮬레이션 그대로 → 출구로 빠지는 순서가 결과
- 💣 **폭탄**: 폭발 시점이 매 라운드마다 무작위 결정. 폭발 시점에 위치한 사람이 걸림
- 🔴 **룰렛**: matter.js 물리 시뮬레이션 그대로 → 칸에 빠진 순서가 결과

**페이크 아웃과의 관계**
- 페이크 아웃은 **결과를 바꾸지 않는다.** 단지 "긴박해 보이는 순간"의 시각 효과.
- 트리거 기반 또는 시각적 페이크 (예: 폭탄의 "거짓 폭발"). 결과 자체는 변경되지 않음.

**당첨 방식과의 관계 (v1.2 신규)**
- 게임은 항상 **참가자 전원의 도착/탈락 순서(rank 1 ~ n)** 를 만들어낸다.
- 그 순서에서 **어떤 순위가 당첨인지**는 게임 후 단계에서 결정된다.
  - 첫번째 모드: rank 1 ~ k
  - 마지막 모드: rank (n-k+1) ~ n
  - 직접 입력 모드: 사용자가 지정한 k개 순위
- 따라서 게임 시뮬레이션은 항상 **전체 순위표를 만들어내야 함** (당첨 방식이 무엇이든 영향 받지 않음).

### 3.3 게임 시간 정책
| 항목 | 값 |
|---|---|
| 게임 최소 길이 | **10초** (인트로 3.5초 제외 순수 플레이 시간) |
| 게임 최대 길이 | **90초** (1분 30초) |
| 페이크 아웃 발동 시 추가 시간 | 게임당 합산 ≤ 8초 |
| 슬로우모션 누적 시간 | 게임당 ≤ 3초 |

**직접 입력 모드의 시간 영향 (v1.2 신규)**
- 폭탄 게임에서 max(당첨 순위) 만큼 폭발 라운드가 진행됨
- 예: 당첨 순위가 [1, 5, 7]이면 7회 폭발 필요 (k=3이지만 끝까지 가야 7등이 나옴)
- max 순위가 클수록 게임 시간 ↑. 90초 한도 초과 위험 시: 폭탄 가속도를 더 강하게 자동 조정
- 메인 화면에서 입력 시 예상 시간이 한도 초과면 경고 표시

### 3.4 접근성 / 광과민성 대응

**WCAG 2.1 가이드라인 준수**
- 큰 면적의 빨간 플래시 금지
- **1초당 3회 이상의 플래시 금지** (대각선 25% 이상 면적 기준)

**연출 강도 토글** (메인 화면 우측 상단 + 설정)
| 모드 | 적용 |
|---|---|
| **Full** (default) | 모든 연출 그대로 |
| **Soft** | 플래시 빈도 50% ↓, 화면 흔들림 50% ↓, 색상 채도 90% |
| **Off** | 플래시·흔들림 제거, 슬로우모션·줌은 유지, 색상 펄스만 |

**자동 감지**
- `prefers-reduced-motion: reduce` 보고 시 첫 방문 자동 **Soft**로 시작

**키보드 / 포커스**
- Tab: 입력 → k → 당첨 방식 → 연출 강도 → 게임 카드
- ESC: 게임 중 → 메인 화면 (확인 모달)
- Enter / Space: 포커스된 게임 카드 시작

## 5. 화면 구성 및 플로우

### 5.1 화면 목록
1. **메인 화면 (Home)** — 참가자 입력 + k 설정 + 당첨 방식 + 연출 강도 + 게임 4종 선택
2. **게임 인트로 (Intro)** — 카운트다운 3-2-1 + 게임 배경
3. **게임 플레이 (Play)** — 각 게임별 진행 화면
4. **결과 화면 (Result)** — 당첨자 발표 + Confetti + 액션 버튼

### 5.2 플로우 다이어그램

```
[Home]
  ├─ 참가자 입력 (textarea, 쉼표/엔터/공백 파싱, 동명이인 자동 접미)
  ├─ k 설정 (1 ≤ k < n)
  ├─ 당첨 방식 (첫번째 / 마지막 / 직접 입력)
  │    └─ 직접 입력 시: k개의 순위 입력 (1 ≤ x ≤ n, 중복 불가)
  ├─ 연출 강도 토글 (Full / Soft / Off)
  └─ 게임 카드 4종 (권장 인원 배지)
       │
       ▼ (게임 선택)
[Intro]
  ├─ 게임 배경 이미지
  ├─ 카운트다운 3 → 2 → 1 → GO!
  └─ 카메라 줌인 효과
       │
       ▼ (자동 전환)
[Play]
  ├─ 게임별 메커니즘 진행 (Step-based Random)
  ├─ 페이크 아웃 (결과를 바꾸지 않는 연출)
  └─ 결정 순간: 슬로우모션 + 화면 흔들림 + 플래시 (강도는 토글에 따름)
       │
       ▼ (자동 전환)
[Result]
  ├─ 당첨자 이름 전광판 (k명 그리드, 순위 배지 표시)
  ├─ Confetti 폭발
  ├─ "다시 하기" → [Home] (참가자·옵션 유지)
  └─ "처음으로" → [Home] (전체 리셋)
```

### 5.3 화면 전환 규칙
- 모든 전환은 Framer Motion 페이드/슬라이드
- 사용자 개입 없이 자동 진행 (Intro → Play → Result)
- [Result]에서만 사용자 액션 대기
- ESC: 어디서든 메인 화면으로 (확인 모달)

```
│ [연출 강도]      ◉ Full  ○ Soft  ○ Off          │
├──────────────────────────────────────────────────┤
│ [게임 선택]                                        │
│  ┌──────┐ ┌──────┐ ┌──────┐ ┌──────┐         │
│  │ 🐎   │ │ 🎱   │ │ 💣   │ │ 🔴   │         │
│  │ 경주마│ │ 로또 │ │ 폭탄 │ │ 룰렛 │         │
│  │~12명 │ │~30명 │ │~20명 │ │~50명 │         │
│  └──────┘ └──────┘ └──────┘ └──────┘         │
└──────────────────────────────────────────────────┘
```

### 6.3 참가자 입력 사양

**파싱 규칙**
- 입력 구분자: **쉼표 `,`**, **줄바꿈 `\n`**, **공백 ` `** 셋 다 인정
- **multiplier syntax (`이름*N`)는 지원하지 않음** — `*` 문자는 일반 문자로 취급
- **동명이인 처리**: 같은 이름이 여러 번 등장하면 자동으로 `#1`, `#2`, ... 접미. 입력 textarea에는 사용자가 친 그대로 두고, 내부 `participants` 배열에서만 접미 (이모지 칩 표시 시에는 접미 노출).
- 빈 문자열 자동 제거
- 최대 글자 수: 이름당 20자 (초과 시 잘림 + 잘렸음 표시)
- 이름 정규화: 양 끝 공백 제거, 연속 공백 1개로
- 최대 인원: **50명** (전체 하드 상한)

**시각화**
- 입력 직후 이름 아래 **이모지 칩**으로 표시
- 이모지 풀 (60+종): 동물 + 과일 + 음식 + 천체
  ```
  🦊🐯🐰🐼🐨🦁🐶🐱🐸🦄🐲🐹🦝🐻🐷🐮🐔🐧🦉🦅
  🦋🐢🐙🦖🦕🐳🦈🐬🦓🦒🦘🦔🦦🦥🦨🦩🦚🦜🦡🐊🐺
  🍎🍊🍋🍌🍉🍇🍓🍒🍑🥝🥭🍍🥥
  🍕🍔🍟🌮🍣🍱🍙🍰🧁🍩🍪
  ⭐🌟✨🌙☄️🪐🌍🌈🔥⚡
  ```
- 이름별 안정적 매핑 (FNV-1a 해시 기반: 같은 이름은 항상 같은 이모지)

**자동 저장**
- 입력 변경 시 **debounce 500ms** 후 localStorage 저장
- 다음 방문 시 자동 복원 (당첨 방식·직접 입력값 포함)

### 6.4 당첨자 수 (k) 설정
- 입력 UI: **`-` / 숫자 / `+` 버튼**
- 범위: `1 ≤ k < n` (참가자 수 미만)
- 참가자 수 변경 시 자동 보정
- **당첨 방식이 '직접 입력'일 때 k 변경**: 입력값 길이가 k와 다르면 빨간 경고 + 게임 카드 비활성화
- 디폴트값: 1

### 6.5 당첨 방식 (v1.2 신규 — 가장 큰 변경)

**3가지 모드**
1. **첫번째 (default)**: 1등부터 k명이 당첨
   - 예: n=10, k=3 → 1·2·3등 당첨
2. **마지막**: 꼴등부터 k명이 당첨
   - 예: n=10, k=3 → 8·9·10등 당첨
3. **직접 입력**: 사용자가 k개 순위를 직접 지목
   - 예: n=10, k=3 → "1, 5, 7" → 1·5·7등 당첨

**직접 입력 모드 명세**

*입력 형식*
- 텍스트 입력란 1개
- 구분자: 쉼표 `,` 또는 공백 ` ` (혼용 가능)
- 자동 정렬해서 표시 (UX, 내부 저장은 입력 순서 유지)
- 입력 예시 placeholder: `"1, 5, 7" 또는 "1 5 7"`

*검증 규칙*
| 조건 | 처리 |
|---|---|
| 입력 개수 ≠ k | 경고 메시지 "k개의 순위를 입력해주세요 (현재 X개)" + 게임 카드 비활성화 |
| 동일 순위 중복 | 경고 "중복된 순위가 있어요: X등" + 게임 카드 비활성화 |
| 순위 < 1 또는 순위 > n | 경고 "X등은 참가자 수(N명) 범위 밖이에요" + 게임 카드 비활성화 |
| 숫자 외 문자 입력 | 입력 단계에서 무시 (숫자·구분자만 허용) |

*검증 통과 표시*
- 입력란 우측에 ✓ 또는 ✗ 아이콘 + 미리보기 ("3명 OK / 1·5·7등")

*자동 저장*
- 직접 입력값도 localStorage에 저장 (`winnerRanks: [1, 5, 7]`)

**게임별 의미** (당첨 방식별)

| 게임 | 첫번째 모드 | 마지막 모드 | 직접 입력 모드 |
|---|---|---|---|
| 경주마 | 결승선 1등 ~ k등 | 결승선 (n-k+1)등 ~ n등 | 결승선 통과 X번째에 도착한 사람들 |
| 로또 | 첫 추출 k개 공 | 마지막까지 남은 k개 공 | X번째 추출되는 공 (전체 추출 시뮬 후 X번째 추출분 선정) |
| 폭탄 | 첫 폭발 ~ k회째 폭발에 걸린 사람 | 마지막에 살아남은 k명 | X번째 폭발에 걸린 사람 (총 max(X)회 폭발 진행) |
| 룰렛 | 가장 먼저 칸에 빠지는 k개 공 | 가장 마지막에 빠지는 k개 공 | X번째로 칸에 빠지는 공 |

**핵심 시뮬 정책**
- 모든 게임은 **참가자 전원의 rank 1 ~ n 순위표를 자연스럽게 만들어낸다**.
- 당첨 방식은 그 순위표에서 *어떤 위치*를 골라낼지의 차이일 뿐이다.
- 따라서 `winnerMode`나 `winnerRanks`는 시뮬레이션 자체에는 영향을 주지 않는다.

**예외: 폭탄 게임의 시간 영향**
- 폭탄은 매 라운드마다 1명을 결정하므로, max(rank)만큼 라운드가 필요
- 첫번째 모드 k=3 → 3라운드
- 마지막 모드 k=3 → n-1 라운드 (마지막 1명 살아남음)
- 직접 입력 모드 [1, 5, 7] → 7라운드
- 총 시간이 90초를 초과할 위험이 있으면 폭탄 가속을 더 강하게 자동 조정 (Phase 4에서 튜닝)

### 6.6 게임 선택 카드
- 카드 4개를 가로 그리드로 배치
- 각 카드에 표시:
  - 큰 이모지 + 게임명
  - **권장 인원 배지** (예: "👥 권장 12명 이하")
  - 호버 시 글로우 + 살짝 위로 떠오르는 모션
- **참가자 수가 권장치 초과 시**: 카드에 회색 오버레이 + "⚠️ 권장 초과" 배지 (선택은 가능)
- **다음 조건 중 하나라도 해당하면 카드 비활성화**:
  - n < 2
  - k = 0 또는 k ≥ n
  - 당첨 방식 = 직접 입력 + 검증 실패 (개수/중복/범위)

### 6.7 인원 적응형 UX 규칙

| 인원 수 | 영향 |
|---|---|
| n < 2 | 모든 게임 비활성화 + "최소 2명 필요" 안내 |
| n > 권장치 | 해당 게임 카드에 경고 배지 (선택은 가능) |
| n > 50 | 입력 자체 차단 (50명 초과분 무시 + 안내 토스트) |
| k ≥ n | k를 n-1로 자동 클램프 |

## 7. 게임별 상세 명세

### 7.1 공통 인트로 시퀀스

**카운트다운 인트로 (총 3.5초, 게임 시간에 미포함)**
1. 게임 배경 이미지 페이드 인 (0.5초)
2. 큰 숫자 "3" 등장 → "2" → "1" (각 0.8초, 카메라 줌인 효과)
3. "GO!" 플래시 (0.3초)
4. 자동으로 게임 플레이 화면 전환

### 7.2 공통 결정 순간 연출

**모든 게임의 "결과 확정 직전"에 적용** (연출 강도 토글에 따라 가감)
- **슬로우 모션**: 결정 0.3~0.5초 전 시간 흐름 30%로 감속
- **화면 흔들림 (shake)**: 결정 순간 0.2초간 진동 (Soft 모드 시 절반, Off 모드 시 미적용)
- **플래시**: 결정 순간 화면 전체 0.1초 백색 플래시 (Off 모드 시 미적용, **WCAG: 1초당 1회 이하**)
- **줌인**: 당첨 대상에 카메라 줌

**직접 입력 모드의 결정 순간 (v1.2 신규)**
- 게임 진행 중 매 도착/탈락마다 화면에 **순위 카운터** 표시 (예: "1등, 2등, … 7등")
- 당첨 순위에 해당하는 도착에서만 슬로우모션 + 플래시
- 비당첨 순위 도착은 평범한 통과 효과만

### 7.3 페이크 아웃 시스템

**핵심 원칙**: "**매번 다른 페이크 아웃**" — 결과를 바꾸지 않으면서 긴장감만 부여

**구현 방식**
- 게임 시작 시 페이크 아웃 개수를 무작위 추첨: **0개 25% / 1개 55% / 2개 20%**
- 게임마다 페이크 아웃 패턴 풀이 다름 (각 게임의 §7.4~7.7 참조)
- 같은 패턴이 직전 게임과 연달아 나오지 않도록 **last-pattern memo** 유지 (메모리만, 영구 저장 안 함)
- 페이크 아웃은 **결과 결정에 영향을 주지 않는 시각 효과**임을 보장

### 7.4 🐎 게임 1: 경주마 (Horse Race)

**기본 메커니즘**
- 가로형 트랙 (좌→우), 결승선 우측
- 각 참가자가 말 캐릭터 (이름표 + 이모지)
- **매 프레임 무작위 가속도 변동** (`randFloat()` 기반)
- 결승선 도달 순서가 그대로 순위
- **참가자 전원의 rank 1 ~ n을 모두 산출** (당첨 방식과 무관)

**Step-based Random 적용**
- 미리 결정된 결과 없음. 시뮬레이션 그대로가 결과.
- 가속도 분포: 평균 = 트랙 길이 / 목표 시간(15초), 표준편차로 변동성 부여
- 마지막 20% 구간에서 변동성 살짝 감소 (사진판정 트리거 빈도 ↑)

**시각 디자인**
- 트랙: 잔디 패턴 + 레인 라인
- 말: SVG 캐릭터 (간단한 도형 조합 + 이모지 헤드)
- 이름표: 말 위에 떠있는 라벨

**페이크 아웃 풀** (랜덤 0~2개)
- 🏁 **막판 흔들림**: 1위가 결승선 30m 전 일시적 감속 → 2위와 격차 좁힘 (단, 1위 유지)
- 📸 **사진판정 연출**: 1·2위 격차가 자연스럽게 5% 이내일 때 자동 발동
- 🐴 **다크호스 시각효과**: 중반 후미 말에 글로우/스파크 (실제 가속도는 그대로)
- 🌪️ **스턴 마크**: 1위에 흙먼지 파티클이 잠깐 끼어 시야 가리기

**결승선 직전 연출**
- 자동 슬로우모션 (마지막 0.5초)
- 카메라 줌인
- **당첨 순위(들)에 해당하는 라인에 골든 라인 효과** (직접 입력 모드일 때 1·5·7번째 도착선만)

**권장 인원**: 2~12명 / **목표 게임 길이**: 12~20초

### 7.5 🎱 게임 2: 럭키 로또 (Lucky Lotto)

**기본 메커니즘**
- 투명한 추첨기에 이름이 적힌 공들이 떠다님 (matter.js 물리)
- 추첨기가 회전하며 공들이 섞임
- **공이 차례로 출구로 추출됨 (전체 n개 추출 가능, 시뮬은 적어도 max(rank)까지 진행)**
- 참가자 전원 rank 산출 가능

**시각 디자인**
- 추첨기: 큰 원형 통 (네온 글로우)
- 공: 컬러풀한 구체 + 중앙에 이름
- 출구: 통 하단의 짧은 튜브
- **추출 순서 카운터** (직접 입력 모드일 때 화면 한쪽에 표시)

**페이크 아웃 풀** (랜덤 0~2개)
- 🎯 **출구 멈칫**: 출구 근처에서 일시적 마찰력 ↑로 공이 잠깐 멈춤
- 🔄 **2공 경합**: 출구 주변에 2~3공이 모이게 토크 미세 조정
- ⏸️ **회전 정지**: 추첨기 토크가 0초간 멈췄다가 다시 회전
- 🌀 **역회전**: 토크 방향이 갑자기 반대로

**추출 연출**
- 당첨 순위 공이 추출되는 순간만 슬로우모션 + 클로즈업
- 비당첨 순위는 평범한 추출 효과
- 이름이 빛나는 텍스트로 확대

**권장 인원**: 2~30명 / **목표 게임 길이**: 10~18초

### 7.6 💣 게임 3: 폭탄 돌리기 (Time Bomb)

**기본 메커니즘**
- 이름들이 원형으로 배치
- 중앙에서 불꽃(스파크)이 한 사람씩 점프
- 점프 속도가 점점 빨라짐
- **무작위 시점에 폭탄 폭발** → 그 시점에 불꽃이 있던 사람이 "걸림"
- **max(당첨 순위)만큼 라운드 진행** (각 라운드 = 1명 결정)

**Step-based Random 적용**
- 폭발 시점은 매 폭발마다 `randInt`로 결정 (3~10초 사이)
- 폭발 시점에 불꽃이 누구한테 있을지는 시뮬 그대로

**시각 디자인**
- 원형 배치, 중앙에 폭탄 이미지
- 불꽃은 폭탄 도화선이 타들어가는 형태
- 사람마다 박스 + 이름 + 이모지
- **라운드 카운터**: 화면 상단 "Round X / Total" (직접 입력 모드일 때 max 라운드 표시)

**타이밍 로직 (시간 한도 90초 보장)**
- 라운드 수 ≤ 5: 라운드당 평균 5초 (자연스러운 페이스)
- 라운드 수 6~12: 라운드당 평균 4초
- 라운드 수 13~20: 라운드당 평균 3초 (가속 강도 ↑)

**페이크 아웃 풀** (랜덤 0~2개)
- ⏸️ **카운트다운 정지**: 불꽃이 한 칸에서 잠깐 정지 → 다시 이동
- 💨 **속도 변화**: 일시 감속 → 폭주 (총 시간 보존)
- 🔥 **거짓 폭발**: 폭발 효과 한 번 나오고 "휴…" 후 진짜 폭발
- 🔄 **방향 반전**: 시계방향 → 반시계방향 갑자기 전환

**폭발 연출 / 라운드 마무리**
- 화면 흔들림 + 백색 플래시 (강도 토글에 따름)
- 폭탄 그래픽 폭발 애니메이션
- 걸린 사람이 *당첨 순위*에 해당하면 추가 강조 (골든 라이트 + 클로즈업)
- 비당첨 순위면 평범한 폭발 후 다음 라운드
- 걸린 사람은 화면 가장자리로 이동, 나머지는 원형 배치 자동 재정렬

**권장 인원**: 2~20명 / **목표 게임 길이**: 10~25초 (max rank에 따라)

### 7.7 🔴 게임 4: 물리 룰렛 (Physics Roulette) — lazygyu 레퍼런스

**기본 메커니즘** (lazygyu 스타일)
- 화면 상단에서 *n*개의 빨간 공이 떨어짐 (참가자 수만큼)
  - 또는 시뮬 효율을 위해 max(rank)개만 떨어뜨려도 됨
  - 직접 입력 모드일 때는 max(rank) 만큼만
- 중간에 못(pegs)이 격자 형태로 박혀 있음
- 공이 못에 부딪히며 좌우로 튐 (matter.js)
- 화면 하단에 이름이 적힌 칸들이 가로로 배치
- **공이 빠진 순서 = rank** → 당첨 순위에 해당하는 공의 칸이 당첨

**Step-based Random 적용**
- matter.js 시뮬레이션 그대로 결과
- 공의 초기 x좌표·초기 속도에 약간의 `randFloat` 노이즈
- 결과 강제 없음

**시각 디자인**
- 어두운 배경 + 네온 못
- 공은 글로우 트레일 효과 (공마다 색상 다름)
- 칸은 무지개 색 그라데이션
- 떨어지면서 트레일이 잔상으로 남음
- **도착 순위 카운터** (직접 입력 모드)

**물리 엔진 파라미터** (튜닝 기준)
- 중력: 1.0 (기본)
- 공 반발력(restitution): 0.4
- 공 마찰: 0.05
- 못 정적 객체로 배치
- 못 격자는 인원수에 따라 자동 조정

**페이크 아웃 풀** (랜덤 0~2개)
- 🪤 **경계선 멈칫**: 두 칸 경계 위 못의 마찰을 일시 ↑
- 🔄 **마지막 튐**: 칸 직전 못의 반발력을 일시 ↑
- 🎯 **연속 추격**: 여러 공이 가까이 붙어 떨어지게 타이밍 미세 조정
- 💫 **느린 낙하**: 한 공이 일시적으로 중력 0.7배

**결정 순간 연출**
- 당첨 순위에 해당하는 공이 칸에 빠지는 순간 슬로우모션 + 칸 강조
- 비당첨 순위는 평범한 도착 효과
- 모든 당첨 순위가 결정될 때까지 시뮬 진행

**인원 수에 따른 칸 배치**
| 인원 | 칸 폭 | 못 격자 |
|---|---|---|
| 2~10명 | 큰 칸 | 듬성듬성 |
| 11~25명 | 중간 | 보통 |
| 26~50명 | 좁은 칸 (식별 가능 폰트) | 촘촘 |

**권장 인원**: 2~50명 / **목표 게임 길이**: 15~30초

## 8. 결과 화면 상세 명세

### 8.1 헤드라인 (당첨 방식에 따라)
- **첫번째 모드**: "🎉 당첨자가 결정되었습니다! 🎉"
- **마지막 모드**: "🎯 운명의 마지막 k명! 🎯"
- **직접 입력 모드**: "🎲 X·Y·Z등 당첨자입니다! 🎲" (실제 입력한 순위 표시)

### 8.2 k에 따른 박스 레이아웃
| k | 레이아웃 | 박스 크기 |
|---|---|---|
| 1 | 화면 중앙 단일 박스 | 매우 큼 (60vw × 40vh) |
| 2 | 가로 2분할 | 큼 |
| 3 | 가로 3분할 | 중간 |
| 4 | 2×2 그리드 | 중간 |
| 5~6 | 3×2 그리드 | 작음 |
| 7~12 | 4×3 그리드 | 작음 (이름 폰트 자동 축소) |
| 13+ | 가로 스크롤 가능한 행 + 자동 폰트 축소 | 매우 작음 |

**순위 배지 (v1.2 신규)**
- 각 박스 좌상단에 **순위 배지** (예: "🥇 1등", "🥈 5등", "🥉 7등")
- 첫번째/마지막 모드: 1·2·3등 또는 (n-2)·(n-1)·n등
- 직접 입력 모드: 사용자가 입력한 순위 그대로

### 8.3 등장 순서
- **첫번째 모드**: 1등(가장 먼저 결정된)부터 0.4초 간격으로 박스 등장
- **마지막 모드**: 마지막에 결정된 사람부터 거꾸로 등장
- **직접 입력 모드**: 입력 순위가 작은 순부터 (1·5·7 → 1등 먼저)

### 8.4 연출
- 당첨자 이름 박스: **전광판 스타일** (디지털 폰트, 글로우)
- 박스 등장 시 타이핑 효과 + 글리치 애니메이션
- **canvas-confetti**로 색종이 폭발 (3초간 지속, k>3이면 4초)
- 배경에 네온 라이트 펄스 효과 (Off 모드 시 정적 배경)

### 8.5 액션 버튼
- **다시 하기**: 같은 참가자·k·당첨 방식·연출 강도 유지하고 메인 화면으로
- **처음으로**: 참가자 목록만 리셋 (옵션은 유지)
- **게임 다시**: 같은 게임을 즉시 다시 (참가자·옵션 유지, 게임 선택 화면 건너뜀)

- ☐ 라운드 수가 많아도 90초 안에 게임이 끝나는가?
- ☐ 룰렛 공이 못에 부딪히며 자연스럽게 떨어지는가?
- ☐ 룰렛 결과 rank가 자연스럽게 산출되는가?
- ☐ **룰렛에서 직접 입력 [1, 5, 7] 모드가 정확히 동작하는가?**
- ☐ 페이크 아웃이 결과를 *바꾸지 않는지* 검증 (시드 주입)

**작업**

- ☐ 직접 입력 모드 헤드라인이 입력 순위를 정확히 표시하는가?

## 12. Phase 진행 규칙

각 Phase의 코드를 작성한 후:

1. 작성한 코드를 보여드립니다.
2. **검증 포인트 체크리스트**를 함께 제시합니다.
3. 사용자가 직접 실행해보고 ☐ → ☑로 체크합니다.
4. 모든 항목이 통과되면 다음 Phase로 진행합니다.
5. 통과 안 되는 항목이 있으면 그 자리에서 수정합니다.

**Phase를 건너뛰거나 멋대로 다음으로 넘어가지 않습니다.**

## 13. 테스트 전략

### 13.1 단위 테스트 (Vitest)
- `randInt`, `randFloat`: 1만 회 호출 후 카이제곱 검정으로 균등성 검증
- 입력 파서: 혼합 구분자, 동명이인, multiplier 미지원, 50명 초과 케이스
- 이모지 매핑 (FNV-1a): 같은 이름 → 같은 이모지
- k 클램프
- **당첨 방식 검증 로직 (v1.2 신규)**: 개수/중복/범위 케이스 전부

### 13.2 게임 로직 테스트 (시드 주입 모드)
- `import.meta.env.MODE === 'test'`일 때 mulberry32 PRNG로 대체
- 같은 시드 → 같은 결과 (재현성)
- **각 게임이 전체 rank 1~n을 산출하는지 검증**
- **당첨 방식 = first/last/custom일 때 winners 배열이 정확한지 검증**
- 페이크 아웃이 결과를 바꾸지 않음을 검증

### 13.3 수동 검증
- 각 Phase의 검증 포인트 체크리스트 (§11)
